 STEP 0 - One-time configuration
---------------------------------------------------------------------
1. git config --global user.name "Sumit Akhuli"
   Sets the author name that is stored in every commit I create.

2. git config --global user.email "sumitakhuli5022@gmail.com"
   Sets the author e-mail recorded with each commit (should match GitHub).

---------------------------------------------------------------------
 STEP 1 - Local repository setup
---------------------------------------------------------------------
3. git init -b main
   Creates an empty Git repository (.git folder) in the project folder
   and names the default branch "main".

4. git status
   Shows the state of the working tree: untracked, modified and staged files.

---------------------------------------------------------------------
 STEP 2 - Git workflow (commits, branch, merge)
---------------------------------------------------------------------
5. git add index.html about.html
   Moves the two HTML files into the staging area so they go in the next commit.

6. git commit -m "Initial commit: add home and about pages"
   Records the staged snapshot permanently in the history with a message.

7. git add about.html
   Stages the modified about.html (skills section added).

8. git commit -m "Update about page with skills section"
   Creates the second commit containing the change to about.html.

9. git branch feature
   Creates a new branch called "feature" pointing at the current commit.

10. git branch
    Lists all local branches; the current branch is marked with *.

11. git switch feature
    Moves HEAD to the feature branch so new commits are made there.

12. git add index.html
    Stages the contact section that was added to index.html.

13. git commit -m "Add contact section to home page"
    Commits the change on the feature branch only (main is unaffected).

14. git switch main
    Returns to the main branch; index.html goes back to main's version.

15. git merge --no-ff feature -m "Merge branch 'feature' into main"
    Merges feature into main. --no-ff forces a merge commit so the branch
    activity remains visible in the history graph.

16. git log --oneline --graph --all --decorate
    Shows the full commit history of all branches as a compact graph.

---------------------------------------------------------------------
 STEP 3 - .gitignore
---------------------------------------------------------------------
17. git status --ignored
    Lists the files Git is ignoring (app.log, temp/) to prove .gitignore works.

18. git add .gitignore
    Stages only the .gitignore file (ignored files are never staged).

19. git commit -m "Add .gitignore for log files and temp folder"
    Commits the ignore rules so they apply for everyone who clones the repo.

---------------------------------------------------------------------
 STEP 4 - Undo operation
---------------------------------------------------------------------
20. git add index.html
    Stages the footer that was added only to demonstrate an undo.

21. git commit -m "Add footer to home page"
    Makes the additional commit that will be undone.

22. git log --oneline -3
    Shows the three most recent commits before undoing.

23. git revert HEAD --no-edit
    Undoes the last commit by creating a new commit that reverses its
    changes. History is not rewritten, so it is safe for a shared/public repo.

24. git log --oneline -4
    Shows the "Revert ..." commit on top, proving the undo was recorded.

25. git show --stat HEAD
    Displays which file the revert commit changed and how many lines.

---------------------------------------------------------------------
 STEP 5 - GitHub integration
---------------------------------------------------------------------
26. git remote add origin https://github.com/sumitakhuli/sdp-git-workflow.git
    Links the local repository to the empty public GitHub repository.

27. git remote -v
    Verifies the fetch and push URLs of the remote named "origin".

28. git push -u origin main
    Uploads main and all its commits to GitHub and sets origin/main
    as the upstream so later pushes need only "git push".

29. git push origin feature
    Publishes the feature branch too, so branch activity is visible on GitHub.

---------------------------------------------------------------------
 STEP 6 - Command documentation
---------------------------------------------------------------------
30. git add git_commands.txt
    Stages this documentation file.

31. git commit -m "Add git command documentation"
    Commits the documentation file.

32. git push
    Pushes the latest commit to GitHub using the upstream set earlier.

33. git log --oneline --graph --all
    Final view of the complete history after all operations.
